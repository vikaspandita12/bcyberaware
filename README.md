## About

BCyberAware is an AI-powered Threat Intelligence Dashboard designed to help individuals and organisations stay informed about the latest cybersecurity threats, vulnerabilities, and best practices.

## Features

- Real-time threat intelligence from **55 sources** — government CERTs (CISA KEV, CERT-In, CERT-EU, NCSC UK, JPCERT/CC, CCCS Canada, CERT-FR, CIS), NVD, GitHub Security Advisories (GHSA, with Atom fallback when the API rate-limits), ZDI 0-day pipeline, vendor PSIRTs (Cisco, Palo Alto, FortiGuard, Microsoft), elite threat labs (CrowdStrike, Mandiant, Unit 42, Talos, Check Point, Sophos X-Ops, Rapid7, Project Zero, Securelist, ESET, SentinelLABS, watchTowr, Tenable), and 20+ global/Indian security newsrooms. Sources refresh on a rotating priority schedule so the Worker stays under Cloudflare's 50-subrequest cap and no source is permanently DOWN
- **🎯 FIRST.org EPSS & CVSS Enrichment** — every CVE-bearing advisory is enriched in real time with its 30-day Exploit Prediction Scoring System (EPSS %) probability and percentile, plus CVSS base score and **⚔️ MITRE ATT&CK** technique tags
- **● DEFCON Cyber Posture Indicator** — live global posture level in the top bar computed from active exploitation, critical CVE volume, and high-EPSS vulnerabilities
- **🔎 Instant Command Search (`/`, `⌘K`), 7-Day Velocity Chart & Ecosystem Matrix** — filter across all advisories, exploits, news, and social intel at once; click any vendor pill or top-EPSS CVE to filter; sort by Severity, EPSS Risk, or Newest; export any view to **CSV**, **JSON**, or **OASIS STIX 2.1** (OpenCTI / MISP / TAXII / SIEM compatible)
- **🧬 Knowledge Graph (OpenCTI ideas, native)** — live MITRE ATT&CK heat matrix, vendor↔CVE↔technique↔actor relationship graph, actor/malware encyclopedia, Diamond Model counts, and an IOC hunt strip. No OpenCTI server — same Cloudflare Worker site
- **★ Analyst Watchlist & One-Click 🛡️ AI Triage** — pin advisories to a persistent local watchlist or click **🛡️ AI Triage** on any card to send it straight into the AI Threat Analyst for root-cause, hunting IOCs, and remediation steps
- **💬 Social Intel** tab — what the security community is posting right now on infosec.exchange (Mastodon), the `#cybersecurity` fediverse tag, Bluesky (verified security researcher feeds), Hacker News and r/netsec
- **🤖 AI Situation Summary** — a 3-bullet executive brief of the current threat picture, regenerated by Workers AI each time the feed refreshes
- **🕵️ Dark Web Early Warning** — live ransomware victim claims (`ransomware.live` RSS), 30+ tracked ransomware groups (`data.ransomware.live`), public breaches (`HaveIBeenPwned`), and active botnet C2 servers (`abuse.ch Feodo Tracker` + `Cybercrime Tracker`)

- **🤖 GenAI Security tab** — 12 AI threat categories (incl. MCP/tool poisoning, autonomous attack agents, slopsquatting), the **OWASP Top 10 for LLM Applications (2025)** and **OWASP Top 10 for Agentic Applications (2026)**, a **⚔️ AI Offensive Tools** tracker of 20 open-source autonomous pentest agents (Strix, Shannon, PentAGI, HexStrike AI…) with defender guidance, current AI security frameworks and defensive tools (promptfoo, garak, PyRIT, MCP scanners), and a live AI-filtered feed

- **🔔 No-login alerts & 📡 RSS** — a `🔔 Alerts` toggle fires browser notifications for new CRITICAL / exploited-in-the-wild threats (polled every 5 min while a tab is open; nothing stored server-side, no account, no email), and `/feed.xml` serves the full live feed as RSS 2.0 for any feed reader

> **Why no X/Twitter?** The X API no longer offers a free read tier, so there is no cost-free, reliable way to pull posts. Mastodon and Bluesky expose public, key-less APIs and are where most of the infosec community now posts in real time.

## AI Threat Analyst (free)

The floating **🛡️ Ask Threat Analyst** chat runs on [Cloudflare Workers AI](https://developers.cloudflare.com/workers-ai/) — no API key, no third-party account. The free Workers plan includes **10,000 neurons/day** (roughly a few hundred chats with the default model). The assistant is grounded in the live feed snapshot, so it can answer "what's exploited in the wild right now?" from the dashboard's own data.

- Endpoint: `POST /api/chat` (streaming SSE) — see `functions/_shared/chat-core.js`
- Situation summary: generated by the scheduled refresh at most every 30 minutes (≈48 small AI calls/day) and delivered inside the feed response; `GET /api/proxy?action=brief` returns the same stored summary
- Model: set `AI_MODEL` in `wrangler.jsonc` (default `@cf/meta/llama-3.1-8b-instruct-fast`; `@cf/meta/llama-3.3-70b-instruct-fp8-fast` for higher quality at ~6× the neuron cost)
- Guards: per-IP rate limit (20 msgs / 10 min), 1,200-char messages, 8-turn history, cybersecurity-only system prompt
- If the deploy fails on the `ai` binding, make sure the `CLOUDFLARE_API_TOKEN` has **Workers AI → Edit** permission

## Intelligence layer: priority, action guidance, merged stories

Built in `functions/_shared/intel-core.js` (pure functions) and applied on every scheduled refresh.

- **Evidence-based exploitation flags.** `exploit_in_wild` needs evidence: a CISA KEV entry, a CVE that is on KEV, or explicit wording such as "actively exploited". Hypothetical advisory wording ("could be exploited") no longer counts. Public exploit code (Exploit-DB, proof-of-concept) is tracked separately as `exploit_public`.
- **Priority score (0–100)** on every advisory, exploit and news item, with the reasons that produced it: exploitation (KEV 45, reported in the wild 38, public exploit 15), EPSS (up to 15), CVSS or impact class (up to 15), internet-facing product (8), corroboration across sources (up to 10), recency (up to 7), ransomware or tracked actor (5). Bands: **ACT NOW** ≥ 70, **THIS WEEK** ≥ 50, **PLAN** ≥ 30, **MONITOR** below.
- **What-to-do box** on items scoring 50+ or with exploitation evidence: who is affected, what to do now, what to hunt for, and the CISA remediation deadline for KEV entries. The guidance is rule-based (one playbook per type of issue) and says so on the card.
- **Merged stories.** The same story from several outlets becomes one card with an "also reported by" list (TF-IDF similarity over headline and summary, tuned to prefer a missed merge over a wrong one).
- **Top Priorities panel** at the top of the feed, a **Priority** sort, and a **Needs action** filter.
- **Optional AI "in short" line** in the what-to-do box, generated by Workers AI a few items per refresh and rejected unless every CVE id and version number in it appears in the item's own text. Controlled by `AI_ACTION_DETAILS` in `wrangler.jsonc`: `visible` (current) or `hidden` (generated, not shown).

```bash
npm test           # story merging, scoring and guidance against a trimmed copy of the live feed
```

## How the feed stays fresh (automation)

- A **Cron Trigger** runs every 5 minutes (`triggers.crons` in `wrangler.jsonc`). It refreshes the stalest sources, rebuilds the feed, regenerates the AI summary when due, and stores the result in **Workers KV** (binding `FEED_KV`) — even when nobody is visiting.
- Visitors are served that stored snapshot, so no page load waits on upstream sources. If the stored snapshot is ever more than 20 minutes old (cron unhealthy) or KV is not bound, the Worker falls back to building the feed live, as before.
- A refresh that collapses (sources down) never overwrites the last good snapshot.
- `GET /api/proxy?action=status` reports whether the scheduled refresh is healthy (snapshot age, sources live, refresh duration) and intelligence counters (priority bands, action boxes, merged stories, AI details). The **Site health check** GitHub workflow calls it every hour and fails — which emails the repo owner — if the refresh has stopped.
- `GET /api/proxy?action=history` returns daily totals (critical, exploited, advisories, news, sources live) for the last 90 days, recorded hourly.
- The KV namespace needs no manual setup: the binding has no `id`, so `wrangler deploy` creates it on first deploy. The deploy token needs **Workers KV Storage → Edit**. Free-plan budget: about 600 of the 1,000 daily KV writes.
- In the browser: the first feed request starts before the scripts finish loading, the last feed is kept in `localStorage` so a returning visitor sees content instantly, and an open tab refreshes silently every 5 minutes.

## Development

The dashboard UI lives in `src/app.jsx` and is compiled and minified to `app.js` with esbuild (served as a static asset). React is served from `vendor/` on the same origin.

```bash
npm install        # one-time setup
npm run build      # compile + minify src/app.jsx → app.js (run after editing the UI)
npm run dev        # build + local server at http://localhost:8787
npm run deploy     # build + deploy to Cloudflare
```

> **Note:** after editing `src/app.jsx`, run `npm run build` and commit the regenerated `app.js` — the GitHub Action deploys files as-is.
